Implemented: POST /api/search-hotels in apps/api/src/routes/search-hotels.ts. The route validates the body with the shared Zod contract (packages/contracts/src/hotels.ts searchRequestSchema) plus the Phase 4 past-date business rule via injected oday() (UTC business date; deterministic in tests). Invalid requests return 400 code VALIDATION_ERROR with structured field errors and start no Workflow (V01-V07 proven, including strict-object rejection of public scenario controls and malformed JSON). Valid searches get a cryptographically unique hotel-search-<uuid> workflowId/searchId and flow through the shared Temporal Client via a small SearchWorkflowGateway (apps/api/src/services/search-service.ts): start with workflowExecutionTimeout 15 s and no automatic workflow retries, await handle.result(), and map the typed SearchOutcome through the pure mapSearchOutcome (200 success with bestOffer{hotelId,name,supplier,price,priceMinor,currency,priceBasis}, partial, safe supplier statuses; 200 empty "No hotels found"; 502 SUPPLIERS_UNAVAILABLE; 504 SEARCH_TIMEOUT for execution-timeout failures; 503 SEARCH_SERVICE_UNAVAILABLE for submission/result transport failures; 500 INTERNAL_ERROR for defects, with details only in logs). The Temporal client/connection is created once at API startup (apps/api/src/temporal/client.ts, apps/api/src/server.ts) and reused for every request; the route never opens connections and never calls supplier HTTP; comparison logic stays in Phase 2 domain code.

Disconnect bridge (S17/S19): before workflow.start the route registers a response 'close' listener that treats close with an unfinished response (!res.writableEnded) as client abandonment and sets a per-request disconnected flag; a cancelOnce guard issues handle.cancel() at most once. If the client disconnects while start is in flight, the flag is checked as soon as the handle resolves and the handle is cancelled immediately; the resulting WorkflowFailedError is observed so nothing becomes an unhandled rejection. Normal successful responses remove the listener and never cancel (proven with a cancel spy). All state is per-request; no global handle exists, so concurrent searches stay isolated (one disconnect does not cancel the other - proven with two concurrent controlled requests). No response is ever written after disconnect (res.destroyed/writableEnded/disconnected guards). Central error middleware (apps/api/src/middleware/error-handler.ts) maps body-parser failures to 400 VALIDATION_ERROR and everything else to a safe 500.
